# 视频自动合并功能说明

## 问题背景

当您开启分段录制时，一个4小时的直播会被切分成多个视频文件：
```
主播名_2025-10-30_19-01-00_001.ts  (0-30分钟)
主播名_2025-10-30_19-01-00_002.ts  (30-60分钟)
主播名_2025-10-30_19-01-00_003.ts  (60-90分钟)
...
主播名_2025-10-30_19-01-00_008.ts  (210-240分钟)
```

这会导致：
- ❌ 观看不便，需要逐个打开播放
- ❌ 后期处理麻烦，需要手动合并
- ❌ 占用更多文件

## 解决方案

启用**自动合并功能**后，程序会在录制完成时自动将所有分段合并成一个完整文件：
```
主播名_2025-10-30_19-01-00_完整.ts  (完整4小时)
```

## 配置说明

在 `config/config.ini` 中找到以下配置项：

```ini
# 是否自动合并分段视频（建议开启）
自动合并分段视频(是/否) = 是

# 合并后是否删除分段文件（建议开启以节省空间）
合并后删除分段文件(是/否) = 是
```

## 使用场景

### 场景1：只保留完整视频（推荐）
```ini
分段录制是否开启 = 是              # 录制时分段，避免意外中断导致全部丢失
视频分段时间(秒) = 1800             # 30分钟一段
自动合并分段视频(是/否) = 是        # 自动合并
合并后删除分段文件(是/否) = 是      # 删除分段，只保留完整文件
```

**优点**：
- ✅ 录制过程稳定（分段保存）
- ✅ 最终得到完整视频
- ✅ 节省磁盘空间

### 场景2：同时保留分段和完整视频
```ini
分段录制是否开启 = 是
自动合并分段视频(是/否) = 是
合并后删除分段文件(是/否) = 否      # 保留分段文件
```

**适用于**：
- 需要对特定片段进行二次处理
- 磁盘空间充足
- 希望保留备份

### 场景3：不使用分段录制
```ini
分段录制是否开启 = 否
```

**注意**：不推荐，因为直播录制时间长，一旦中途出错整个文件可能损坏。

## 合并原理

### 技术实现

使用 **FFmpeg concat** 协议进行合并：
```bash
ffmpeg -f concat -safe 0 -i filelist.txt -c copy output.ts
```

**特点**：
- ⚡ **极快**：直接复制流，不重新编码
- 🎯 **无损**：画质和音质完全一致
- 💾 **高效**：4小时视频合并通常只需几秒钟

### 为什么不用其他方法？

| 方法 | 速度 | 质量 | 缺点 |
|------|------|------|------|
| FFmpeg concat | ⚡⚡⚡ 极快 | ✅ 无损 | - |
| 重新编码 | 🐌 很慢 | ⚠️ 有损 | 4小时可能需要1小时+ |
| 视频编辑软件 | 🐢 慢 | ✅ 无损 | 需要手动操作 |

## 手动合并方法

如果您需要手动合并已录制的分段视频：

```bash
cd /home/liu/app_github/DouyinLiveRecorder
```

### 方法2：直接使用FFmpeg

1. 创建文件列表 `filelist.txt`：
```
file '/path/to/主播名_2025-10-30_19-01-00_001.ts'
file '/path/to/主播名_2025-10-30_19-01-00_002.ts'
file '/path/to/主播名_2025-10-30_19-01-00_003.ts'
```

2. 执行合并：
```bash
ffmpeg -f concat -safe 0 -i filelist.txt -c copy output.ts
```

## 注意事项

### 1. 磁盘空间
合并过程中会临时占用双倍空间：
- 原分段文件：假设共10GB
- 合并后文件：约10GB
- **临时需要**：约20GB

合并完成后如果删除分段文件，空间会恢复正常。

### 2. 合并时机
- 程序检测到直播结束后自动触发合并
- 合并过程在后台进行，不影响其他录制
- 合并完成会在日志中显示

### 3. 文件命名
- 分段文件：`主播名_日期时间_001.ts`、`主播名_日期时间_002.ts`...
- 合并文件：`主播名_日期时间_完整.ts`

### 4. 错误处理
如果合并失败：
- ✅ 原分段文件会保留（不会丢失）
- ✅ 日志中会记录错误信息
- ✅ 可以稍后手动合并

## 最佳实践建议

### 推荐配置
```ini
分段录制是否开启 = 是
视频分段时间(秒) = 1800              # 30分钟，平衡稳定性和文件数量
自动合并分段视频(是/否) = 是
合并后删除分段文件(是/否) = 是        # 节省空间
录制完成后自动转为mp4格式 = 否        # 合并后再转换更高效
```

### 工作流程
```
录制开始 → 分段保存(TS格式) → 录制结束 → 自动合并 → 删除分段 → (可选)转MP4
```

### 转码建议
如果需要MP4格式，建议：
1. 先合并成完整TS文件
2. 再转换成MP4

这样比每个分段都转MP4然后再合并要高效得多。

## FAQ

**Q: 合并会降低画质吗？**  
A: 不会。使用 `-c copy` 参数是直接复制流，完全无损。

**Q: 合并需要多长时间？**  
A: 通常只需几秒到几十秒，取决于文件大小和磁盘速度。4小时视频一般10-30秒完成。

**Q: 可以合并不同格式的视频吗？**  
A: 建议不要。本功能设计用于合并同一次录制的分段，它们格式、编码、分辨率都相同。

**Q: 合并失败了怎么办？**  
A: 分段文件会保留，您可以：
1. 查看日志找出错误原因
2. 使用手动合并方法
3. 或者直接使用分段文件

**Q: 能否在录制过程中就开始合并？**  
A: 不建议。等录制完成后合并更安全，避免文件损坏。
