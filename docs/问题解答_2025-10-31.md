## 问题1：批量提取歌曲音频报错 ❌→✅

### 错误信息
```
AttributeError: 'str' object has no attribute 'get'
File "/home/liu/app_github/DouyinLiveRecorder/批量提取歌曲音频.py", line 108
    song_id = song.get("id", f"song_{i:03d}")
              ^^^^^^^^
```

### 原因分析
`歌曲列表.json` 的格式是：
```json
{
  "total_songs": 125,
  "total_duration": 9468.24,
  "songs": [...]
}
```

但在加载时，代码直接用 `json.load(f)` 加载了整个对象，而不是只加载 `songs` 数组。

在循环时试图遍历整个字典对象，导致 `song` 变量是字符串（字典的键），而不是歌曲对象（字典）。

### 解决方案 ✅
修改 `批量提取歌曲音频.py` 第42-51行：

```python
# 加载歌曲列表
with open(song_list_path, 'r', encoding='utf-8') as f:
    data = json.load(f)
    # 如果是字典格式（包含songs键），提取songs数组
    if isinstance(data, dict):
        self.songs = data.get("songs", [])
    else:
        self.songs = data

print(f"已加载 {len(self.songs)} 首歌曲")
```

### 验证
现在可以正常运行：
```bash
python3 批量提取歌曲音频.py
```

## 问题2：歌词准确性问题 💡→✅

### 问题描述
用户建议："有没有一种可能我们去存储上那些歌的原歌词，这样歌词就准了"

### 问题分析
- **现状**：使用Whisper语音转文字生成歌词
- **缺点**：
  - ❌ 识别错误率较高（尤其是快歌、方言）
  - ❌ 同音字混淆（如："爱如母发" vs "爱如覆水"）
  - ❌ 歌词断句不准确
  - ❌ 特殊发音识别失败

- **优点**（Whisper）：
  - ✅ 时间轴准确（与实际演唱同步）
  - ✅ 能处理所有歌曲（即使是冷门/未知歌曲）

### 解决方案 ✅

#### 方案A：网络歌词API（推荐）⭐
**新增工具**：`获取网络歌词.py`

**功能**：
1. 从歌曲列表读取歌名
2. 通过网易云音乐/QQ音乐API搜索歌曲
3. 获取正版LRC歌词
4. 转换为SRT和ASS字幕格式

**优势**：
- ✅ 歌词准确率100%（官方正版）
- ✅ 断句专业（音乐人审核）
- ✅ 自动匹配歌手和专辑信息

**劣势**：
- ⚠️ 时间轴是原版歌曲的，可能与直播演唱不同步
- ⚠️ 无法获取"未知歌曲"的歌词
- ⚠️ 需要网络连接

**使用方法**：
```bash
python3 获取网络歌词.py
```

支持三种模式：
- 测试模式：仅处理前10首
- 全部模式：处理所有125首
- 自定义范围：指定起止索引

**输出**：
- 目录：`~/shanshan_materials/歌词字幕_网络版/`
- 格式：SRT + ASS
- 命名：`001_歌名.srt` / `001_歌名.ass`

#### 方案B：混合方案（最佳）⭐⭐⭐

| 歌曲类型 | 歌词来源 | 时间轴 | 准确度 |
|---------|---------|-------|--------|
| 已知歌曲（有歌名） | 网络API | 需要微调 | ⭐⭐⭐⭐⭐ |
| 未知歌曲 | Whisper | 准确 | ⭐⭐⭐ |

**工作流程**：
1. 运行 `python3 获取网络歌词.py` → 获取正版歌词
2. 对于获取失败的歌曲 → 使用Whisper版本
3. 使用Aegisub等工具微调网络歌词的时间轴

#### 方案C：本地歌词库（备用）

如果有现成的歌词文件：
```
~/shanshan_materials/歌词库/
├── 歌名1.lrc
├── 歌名2.lrc
└── ...
```

可以编写匹配脚本从本地读取。

### 对比表

|------|-------------|---------|---------|
| 歌词准确度 | ⭐⭐⭐ | ⭐⭐⭐⭐⭐ | ⭐⭐⭐⭐⭐ |

| **推荐度** | - | ⭐⭐⭐⭐ | ⭐⭐⭐⭐⭐ |

## 问题3：表情包和剪映草稿为何跳过/可选 ℹ️

### 问题描述
运行一键脚本时，看到：
```
[2025-10-31 19:29:21] WARNING: 阶段7：生成表情包（跳过，如需生成请手动运行）
[2025-10-31 19:29:21] INFO: 阶段8：生成剪映草稿（可选）
```

为什么跳过？

### 原因说明

#### 阶段7：表情包生成（跳过）⚠️

**原因1：耗时非常长**
- 表情包生成需要逐帧分析视频
- 4小时录播视频：
  - 总帧数：~280,000帧
  - 手势检测：需要分析前60分钟（~70,000帧）
  - 运动检测：每秒10-20帧
  - **预计耗时：10-30分钟**

**原因2：不是每次都需要**
- 表情包素材相对固定
- 不需要每天都重新生成
- 只在以下情况需要生成：
  - 主播有新的表情动作
  - 需要更新表情包库
  - 第一次运行系统

**原因3：资源占用大**
- CPU密集型任务
- 需要加载MediaPipe模型
- 内存占用：1-2GB

**何时运行**：
```bash
# 仅在需要时手动运行
python3 生成表情包素材_优化版.py
```

#### 阶段8：剪映草稿（可选）ℹ️

**原因1：根据需求不同**
有两种剪映草稿：
- `生成剪映草稿_歌曲集锦.py` - 歌曲精选集锦
- `生成剪映草稿_完整分段.py` - 完整视频分段

用户可能只需要其中一种，或者两种都不需要（手动剪辑）。

**原因2：不是必需品**
- 剪映草稿是为了方便剪辑
- 但不是所有人都使用剪映
- 可能使用Premiere/DaVinci等其他工具

**原因3：个性化需求高**
- 不同的剪辑需求生成不同的草稿
- 一键脚本无法判断用户需要哪种
- 由用户自行选择更合适

**何时运行**：
```bash
# 需要歌曲集锦时
python3 生成剪映草稿_歌曲集锦.py

# 需要完整分段时
python3 生成剪映草稿_完整分段.py
```

### 一键脚本的设计理念

#### 自动运行（6个阶段）
1. ✅ 内容分类 - **必需**，后续所有功能的基础
2. ✅ 歌曲整理 - **必需**，识别歌曲
3. ✅ 提取音频 - **常用**，快速（1-2分钟）
4. ✅ 生成字幕 - **常用**，快速（<1分钟）
5. ✅ 关键帧截图 - **常用**，快速（<1分钟）
6. ✅ 精彩集锦 - **常用**，快速（1-2分钟）

**总耗时**：约5-10分钟

#### 手动运行（2个阶段）
7. ⚠️ 表情包生成 - **可选**，耗时（10-30分钟）
8. ℹ️ 剪映草稿 - **可选**，根据需求

### 完整处理流程

**每天录制后的标准流程**：
```bash
# 1. 一键处理常用素材（5-10分钟）
bash 一键运行所有脚本.sh

# 2. 获取网络歌词（2-5分钟，推荐）
python3 获取网络歌词.py

# 3. 查看生成的素材
ls ~/shanshan_materials/

# 4. 根据需要生成表情包（可选，10-30分钟）
python3 生成表情包素材_优化版.py

# 5. 根据需要生成剪映草稿（可选，<1分钟）
python3 生成剪映草稿_歌曲集锦.py
python3 生成剪映草稿_完整分段.py

# 6. 同步到网站服务器（可选）
bash 同步到storage定时任务.sh
```

### 如果想要全自动呢？

如果您希望全部自动运行（包括表情包和剪映草稿），可以修改 `一键运行所有脚本.sh`：

**取消注释这两行**：
```bash

# 第175行
run_script "生成剪映草稿_歌曲集锦.py" "生成剪映草稿（歌曲集锦）" "no"
```

**变为**：
```bash

run_script "生成表情包素材_优化版.py" "生成表情包素材" "no"

# 第175行
# run_script "生成剪映草稿_歌曲集锦.py" "生成剪映草稿（歌曲集锦）" "no"
run_script "生成剪映草稿_歌曲集锦.py" "生成剪映草稿（歌曲集锦）" "no"
```

**但注意**：
- 总耗时将增加到15-40分钟
- 不适合在急需素材时使用
